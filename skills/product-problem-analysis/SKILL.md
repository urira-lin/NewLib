# 问题分析

## 使用约定

围绕本轮目标与指定成果推进。区分现状、方案、已确认决定和待补信息；沿用已有决定，集中处理关键分歧。结论前置，检查强度与改动相称。

## 层级与按需参考

本技能属于通用产品方法层。涉及数值差分、跨期归属或查询条件时，读取 [数据调研与核对](../data-metric-definition/references/数据调研与核对.md)；计算定义需要确认时使用 [指标与数据口径](../data-metric-definition/SKILL.md)。

餐饮任务读取 [餐饮业务参考](../product-workflow/references/餐饮业务/业务参考.md) 中与本轮相关的内容；其他行业采用当前项目的角色、对象、竞品和资料。架构与能力记录按产品分别维护。

## 必要输入

问题描述、当前规则、操作记录、系统结果及相关条件；资料只覆盖部分链路时限定结论范围。

## 执行步骤

1. 用一句话界定异常：什么对象、在什么条件下、实际结果与哪条有效规则冲突。没有确认的预期先标为假设。
2. 建立证据清单，分开直接观察、用户报告、研发说明和推断；保留时间、端、样本标识及来源。
3. 沿用户操作→业务记录与状态→系统处理→页面结果定位断点。区分各动作的对象、前置条件和实际后果。
4. 对齐操作时间线与结果，识别同期干扰和不同条件造成的差异。涉及数值快照或时间归属时，使用数据专题中的差分与窗口核对方法。
5. 为主要假设找支持与反证，设计能区分假设的最小补证操作。新证据修正时间线时，更新依赖旧时间线的结论。
6. 输出已证实原因或当前最有依据的假设、影响和下一步。无法验证时保留未决结论；可并行推进不依赖它的工作。

## 输出

问题证据记录、计算或时间线对照、原因判断与最小补证建议。

需要组织成果时读取 [交付模板](assets/交付模板.md)，按本轮成果裁剪填写。

## 完成标准

第三方能按条件复查结论；干扰因素和未知环节清楚；没有从单一截图宣称根因已验证。

## 常见误判

把同时发生当作因果；混用不同条件下的结果；模拟结果当真实系统验证。
